Outline for the Final Report

Proposed structure for presenting the revised interceptor assignment method without making it sound like a restatement of the original DES/FSM framework.

Core framing sentence: The original DES/FSM handover pipeline is retained, but the conflict-resolution formulation is revised in affected-target scope, lexicographic objective, and global assignment structure.

1. Abstract

  • Briefly introduce cooperative multi-target tracking in a mobile WSN.
  • State the limitation of the previous MinMax-based conflict resolution.
  • Explicitly state the three differences of the revised method: expanded affected-target scope, maximize-then-minimize objective, and global assignment structure.
  • Conclude with the main implication: improved conflict handling while preserving distributed DES execution under ideal communication assumptions.

Keywords: affected-target scope, lexicographic objective, global assignment, distributed DES

2. Introduction

  • Introduce why interceptor assignment conflict matters in proactive handover.
  • Explain what the previous paper already achieved: DES/FSM coordination, local bidding, proactive handover.
  • Identify the specific limitation: MinMax only protects fairness within one conflict-resolution step, and later overlapping requests do not automatically pull the previously served target back into the same reassignment scope.
  • End with a short contribution list built around the three explicit differences.

This section should define the novelty early, rather than spending too much space on general WSN background.

3. Background / Previous Framework

  • Summarize the original DES/FSM architecture only to the extent needed for the new method.
  • Describe the original broadcast-bid-select pipeline.
  • Clarify that bid computation remains local and distributed.
  • Present the previous MinMax conflict-resolution logic as the baseline for comparison.

The purpose of this section is to establish what remains unchanged and what serves as the baseline.

4. Problem Formulation

  • Define targets, candidate sensors, interceptor slots, and assignment costs.
  • Formally define affected targets as the current requesting target plus any original target impacted by committed-sensor overlap.
  • Distinguish between synchronous conflict and asynchronous later-request conflict.
  • Explain why a purely local or pairwise team comparison is insufficient once affected targets must be handled in one shared reassignment scope.

5. Revised Method

5.1 What Is Retained from the Original DES Workflow

  • Broadcast, bidding, and selection stages remain.
  • Each sensor still computes its own bid locally.
  • Sensor-level execution remains FSM-based and distributed.

5.2 Revised Affected-Target Scope

  • If a later request contests a sensor already committed to another target, include that original target in the same affected-target set.
  • Handle committed-sensor overlap by expanding the reassignment scope before solving the assignment, rather than by a separate post-selection repair step.

5.3 Revised Objective

  • First maximize the number of assigned interceptor slots across all affected targets.
  • Then minimize the total assignment cost among those maximally feasible solutions.
  • The replacement opportunity for a previously served target emerges from this shared objective once that target is included in the affected-target set.

5.4 Revised Assignment Structure

  • Replace non-overlapping two-sensor team comparison with a global sensor-to-target-slot assignment.
  • Construct the assignment over all affected targets and all eligible candidate sensors in the current reassignment event.

This is the core section of the report and should make the three differences explicit: expanded affected-target scope, revised objective, and revised assignment structure.

6. Distributed Realization and Communication Assumptions

  • Clarify that global refers to the decision scope, not centralized control of the whole WSN.
  • Explain how sensors reconstruct the same assignment instance under ideal communication.
  • State that bids are still generated locally and disseminated through the network.
  • Discuss the practical limitation that communication delay and incomplete message propagation can affect feasibility.

7. Simulation Setup and Comparative Scenario

  • Use the same DES framework, EKF model, bidding cost function, and network parameters as the previous version.
  • State clearly that the interceptor assignment strategy is the only intended methodological difference.
  • Introduce the natural conflict scenario, especially the case where a later request expands the affected-target set by overlapping with a previously committed interceptor.

8. Results and Discussion

  • Compare the assignment outcomes under the same conflict scenario.
  • Explain differences in terms of affected-target scope, objective, and assignment structure, not just numerical cost reduction.
  • Show whether the revised method improves fulfilled interceptor count, total cost, or reassignment robustness once previously served targets are jointly reconsidered.
  • Discuss the trade-off between fairness-oriented MinMax behavior and efficiency-oriented global assignment behavior.

The discussion should emphasize formulation-level differences, not merely algorithm naming differences.

9. Conclusion

  • Restate the three explicit differences from the previous paper: affected-target scope, assignment objective, and assignment structure.
  • Summarize the main benefit of the revised method in conflict handling.
  • Reaffirm that the distributed DES architecture is preserved conceptually.
  • Close with future work on communication-aware and hardware-aware validation.
