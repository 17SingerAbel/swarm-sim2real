Simultaneous Multi-Target Interceptor
Assignment in Mobile WSN

Problem Formulation and Algorithm Design for Proactive Handover Conflict Resolution

CourseMIE8888 — Special Topics
ComponentProactive Handover System — Bug 4 / Design Report
DateMarch 2026
ScopeSimulation (MATLAB), N ≤ 3 targets, k ≤ 25 sensors
Abstract. In a mobile Wireless Sensor Network (WSN) designed for cooperative multi-target tracking, each target is continuously covered by a pair of active tracker sensors. When a tracker predicts it will lose contact, it triggers a proactive interceptor call: idle sensors bid for the role of replacement, and the best two are dispatched to intercept the target before coverage is lost. When multiple targets issue interceptor calls in the same time step, a conflict arises — the same idle sensor may be the top bidder for more than one target. This report formalises that conflict as a Minimax Bottleneck Team Assignment Problem, presents its mathematical model in both general and simulation-specific forms, and proposes five candidate algorithms ranging from exact to near-optimal, with complexity and trade-off analysis for each.

1.Introduction

The simulation implements a proactive handover mechanism for a mobile WSN tracking up to three targets simultaneously. Each target is assigned exactly two active trackers — a PRIMARY and a SECONDARY — that maintain contact using an Extended Kalman Filter (EKF). When a tracker's EKF estimate converges and consecutive loss-time predictions become stable, the tracker broadcasts an interceptor call. Available idle sensors submit bids based on a weighted cost function (displacement from home, distance to intercept point, temporal penalty, uncertainty). The two lowest-bidding sensors are dispatched as replacements.

In a multi-target scenario, two or more targets may enter the selection phase simultaneously. If their independent best teams share a sensor, a conflict exists: assigning that sensor to one target leaves the other without a viable team. The current implementation resolves this for N = 2 targets via a minimax enumeration, but provides no resolution for N = 3 — it silently falls back to an independent greedy assignment that may violate the disjointness requirement.

Identified gap (Bug 4): Line 987 — if length(all_calling_targets) == 2 — the conflict resolver is never entered for three simultaneous callers. The log still prints "ENTERING CONFLICT RESOLUTION PATH" but no optimisation runs, and sensor assignments can collide.

3.Mathematical Model

3.1 Definitions

S = { s₁, s₂, …, sₖ } // pool of available (non-tracker) sensors, k ≤ 22 T = { t₁, t₂, …, t_N } // set of targets simultaneously requesting interceptors, N ≤ 3 B ∈ ℝ^{k × N}, B[i,j] ≥ 0 // bid matrix: cost of sensor sᵢ bidding for target tⱼ (lower = better) Pⱼ ⊆ S, |Pⱼ| = 2 // team assigned to target tⱼ (exactly 2 sensors) Cⱼ = Σ_{s ∈ Pⱼ} B[s, j] // total cost of team j

3.2 Bid cost function

Each sensor computes its bid for a target using a weighted sum of four penalty terms:

B[i, j] = w₁·P_home(i) + w₂·P_spatial(i,j) + w₃·P_temporal(i,j) + w₄·P_uncertainty(i,j) where: P_home(i) = ‖pos(sᵢ) − home(sᵢ)‖ / d_max // displacement from grid position P_spatial(i,j) = ‖pos(sᵢ) − intercept(tⱼ)‖ / d_max // distance to intercept point P_temporal(i,j) = max(0, (τ_arrive − τ_target) / τ_target) // late-arrival penalty P_uncertainty(i) = 1 − confidence(sᵢ) // inverse EKF confidence weights: w₁=0.4, w₂=0.3, w₃=0.2, w₄=0.1

3.3 Constraints

|Pⱼ| = 2 ∀ j ∈ {1,…,N} // exactly 2 sensors per team Pᵢ ∩ Pⱼ = ∅ ∀ i ≠ j // teams are disjoint — no sensor shared ⋃ Pⱼ ⊆ S // all assigned sensors are available

3.4 Objective — Minimax (bottleneck)

minimise max_{j = 1…N} Cⱼ subject to the constraints in §3.3 Equivalent ILP form: min θ s.t. Σᵢ xᵢⱼ = 2 ∀ j // 2 sensors per target Σⱼ xᵢⱼ ≤ 1 ∀ i // each sensor used at most once Σᵢ B[i,j]·xᵢⱼ ≤ θ ∀ j // team cost bounded by bottleneck θ xᵢⱼ ∈ {0, 1}, θ ∈ ℝ⁺
Interpretation: The minimax criterion protects the worst-served target. If one target is assigned a poor team, that team's high cost dominates and is penalised in the objective — the solver is forced to balance quality across all targets rather than optimising an average.

4.Candidate Algorithms

Five algorithms are proposed, covering the spectrum from exact to near-optimal and from simulation-specific to general. Each is assessed on optimality, computational complexity, MATLAB implementation effort, and suitability for real-time use.

1
Extended Exhaustive Enumeration (6-loop) Optimal within top-k

Direct extension of the existing N=2 four-loop minimax block to N=3 with two additional nested loops. All disjoint triplets of 2-sensor teams are enumerated from a shared top-k pool; the one minimising max(C₁, C₂, C₃) is selected.

Complexity: O(k6) raw; with top-8 filter: union pool ≤ 16 → C(16,2)³ ≈ 27,000 iterations. Estimated runtime < 0.5 ms in MATLAB. Well within the 100 ms timestep budget. 
% Step 1 — build top-k pool (identical to N=2 block)
n_top = min(8, length(available_sensors));
[~,si1]=sort(all_target_bids(:,1)); top1=available_sensors(si1(1:n_top));
[~,si2]=sort(all_target_bids(:,2)); top2=available_sensors(si2(1:n_top));
[~,si3]=sort(all_target_bids(:,3)); top3=available_sensors(si3(1:n_top));
top = unique([top1; top2; top3]);   K = length(top);

% Step 2 — enumerate all disjoint triplets
best_cost = inf;  best_assign = [];
for i1 = 1:K-1; for i2 = i1+1:K
  r1 = [top(i1), top(i2)];
  c1 = sum(all_target_bids(ismember(available_sensors,r1), 1));
  if c1 >= best_cost; continue; end   % prune on partial cost

  for i3 = 1:K-1; for i4 = i3+1:K
    if ~isempty(intersect(r1,[top(i3),top(i4)])); continue; end
    r2 = [top(i3), top(i4)];
    c2 = all_target_bids(ismember(available_sensors,r2), 2);
    c2 = sum(c2);
    if max(c1,c2) >= best_cost; continue; end   % prune

    for i5 = 1:K-1; for i6 = i5+1:K
      r3 = [top(i5), top(i6)];
      if ~isempty(intersect(r1,r3)) || ~isempty(intersect(r2,r3)); continue; end
      c3 = sum(all_target_bids(ismember(available_sensors,r3), 3));
      mc = max([c1, c2, c3]);
      if mc < best_cost
        best_cost = mc;
        best_assign = {r1, r2, r3};
      end
    end; end
  end; end
end; end
Strengths
  • ✓ Exact minimax within top-k
  • ✓ Minimal change to existing code
  • ✓ No toolbox dependency
  • ✓ Partial-cost pruning reduces iterations ~60%
Weaknesses
  • ✗ 6 nested loops — hard to read/maintain
  • ✗ Top-k filter may exclude globally optimal sensors
  • ✗ Does not extend beyond N=3 without more loops
2
Integer Linear Program — MATLAB intlinprog Globally Optimal

Encode the problem directly as the ILP from §3.4. MATLAB's built-in branch-and-bound solver (intlinprog) finds the provably optimal assignment over the full sensor pool, with no top-k pruning required. Handles any N automatically.

Complexity: ILP is NP-hard in general; in practice branch-and-bound on 66 binary variables (k=22, N=3) solves in <1 ms. No enumeration required. The number of decision variables scales as O(k·N). 
N_t = length(all_calling_targets);
k   = length(available_sensors);
n_vars = k*N_t + 1;           % [x_11,...,x_kN, theta]

f   = [zeros(1, k*N_t), 1];   % minimise theta

% Equality: 2 sensors per target
Aeq = zeros(N_t, n_vars);
for j = 1:N_t
    Aeq(j, (j-1)*k+1:j*k) = 1;
end
beq = 2*ones(N_t, 1);

% Inequality: each sensor used at most once
A1 = zeros(k, n_vars);
for i = 1:k
    for j = 1:N_t; A1(i,(j-1)*k+i)=1; end
end

% Inequality: team cost <= theta
A2 = zeros(N_t, n_vars);
for j = 1:N_t
    A2(j,(j-1)*k+1:j*k) = all_target_bids(:,j)';
    A2(j,end) = -1;
end

A = [A1; A2]; b = [ones(k,1); zeros(N_t,1)];
lb = zeros(n_vars,1); ub = [ones(k*N_t,1); inf];
opts = optimoptions('intlinprog','Display','off');
[sol,~,flag] = intlinprog(f, 1:k*N_t, A, b, Aeq, beq, lb, ub, opts);
if flag > 0
    X = reshape(sol(1:k*N_t), k, N_t);
    for j = 1:N_t
        best_assign{j} = available_sensors(X(:,j) > 0.5);
    end
end
Strengths
  • ✓ Globally optimal — no pruning
  • ✓ Handles arbitrary N in one formulation
  • ✓ Compact, readable code
Weaknesses
  • ✗ Requires Optimization Toolbox
  • ✗ Black-box solver — harder to explain
  • ✗ License dependency for deployment
3
Permutation Greedy (N! orderings) Near-Optimal

Enumerate all N! orderings of the target list. For each ordering, greedily assign the cheapest available 2-sensor team to each target in sequence (removing used sensors). Return the ordering that achieves the minimum maximum team cost. For N=3 this is only 6 orderings; for N=2 it reduces to the existing logic.

Complexity: O(N! · k²). For N=3, k=22: 6 × 484 ≈ 2,900 operations — negligible. Generalises to any N without code changes; remains tractable for N ≤ 8. 
perm_order = perms(1:N_t);    % N! x N matrix
best_cost  = inf;
best_assign = cell(1, N_t);

for p = 1:size(perm_order,1)
    order = perm_order(p,:);
    used  = [];  teams = cell(1, N_t);  max_c = 0;  ok = true;

    for jj = 1:N_t
        j    = order(jj);
        free = setdiff(1:k, used);
        if length(free) < 2; ok = false; break; end

        best_c = inf;  best_p = [];
        for a = 1:length(free)-1
            for b = a+1:length(free)
                c = all_target_bids(free(a),j) + all_target_bids(free(b),j);
                if c < best_c; best_c = c; best_p = [free(a),free(b)]; end
            end
        end
        used  = [used, best_p];
        teams{j} = available_sensors(best_p);
        max_c = max(max_c, best_c);
    end

    if ok && max_c < best_cost
        best_cost = max_c;  best_assign = teams;
    end
end
Strengths
  • ✓ No toolbox needed
  • ✓ Handles any N with the same code
  • ✓ Most readable of all five
  • ✓ Eliminates N==2 / N==3 branching
Weaknesses
  • ✗ Not guaranteed optimal
  • ✗ Greedy-within-ordering can miss globally optimal allocation
  • ✗ N! grows fast (N=8 → 40,320 orderings)
4
Branch and Bound with Minimax Pruning Optimal

Recursive search over targets. At each node, iterate over all C(k_remaining, 2) teams for the current target. Prune any branch where the partial maximum cost already exceeds the best known complete solution. The bound is tight: the bottleneck can only increase as more teams are assigned, so early pruning is effective.

Complexity: O(k2N) worst case (same as exhaustive), but pruning typically eliminates >90% of branches when the bid spread is non-uniform. Average case much closer to O(N · k²). 
function [best_c, best_a] = bb3(j_remaining, avail_idx, cur_max, ub, partial)
% j_remaining: remaining target indices; avail_idx: available sensor indices
% cur_max: partial bottleneck so far; ub: current best upper bound
    if isempty(j_remaining)
        best_c = cur_max;  best_a = partial;  return;
    end
    j      = j_remaining(1);  rest = j_remaining(2:end);
    best_c = ub;  best_a = [];
    n      = length(avail_idx);
    for a = 1:n-1
        for b = a+1:n
            c_team  = all_target_bids(avail_idx(a),j) + ...
                      all_target_bids(avail_idx(b),j);
            new_max = max(cur_max, c_team);
            if new_max >= best_c; continue; end   % prune
            new_avail = avail_idx(setdiff(1:n,[a,b]));
            [c2,a2] = bb3(rest, new_avail, new_max, best_c, ...
                          [partial, {[avail_idx(a),avail_idx(b)]}]);
            if ~isempty(a2) && c2 < best_c
                best_c = c2;  best_a = a2;
            end
        end
    end
end
% Call: [cost, assign] = bb3(1:N_t, 1:k, 0, inf, {});
Strengths
  • ✓ Provably optimal
  • ✓ No toolbox needed
  • ✓ Very fast when bids are spread out
Weaknesses
  • ✗ Recursion overhead in MATLAB
  • ✗ Worst case = exhaustive enumeration
  • ✗ More complex to debug
5
Threshold Relaxation Scan Near-Optimal

Reformulate as a feasibility problem: is there a valid assignment with all team costs ≤ θ? Sort all possible teams by cost. Iterate θ over the sorted list of distinct team costs. For each θ, greedily check if N disjoint teams all under θ exist. The smallest feasible θ gives the near-minimax solution.

Complexity: O(k² · N · log k) for team generation and sorting + O(C(k,2) · N) for the scan. For k=22, N=3: roughly 5,000 total operations. Sub-optimal because feasibility check is greedy, not exact matching. 
% Pre-sort all teams per target
all_teams = cell(N_t,1);
for j = 1:N_t
    pairs = [];
    for a=1:k-1; for b=a+1:k
        pairs(end+1,:) = [a, b, all_target_bids(a,j)+all_target_bids(b,j)];
    end; end
    [~,si] = sort(pairs(:,3));
    all_teams{j} = pairs(si,:);
end
thresholds = unique(vertcat(all_teams{:})(:,3));

best_theta = inf;  best_assign = {};
for theta = thresholds'
    used=[]; teams={}; ok=true;
    for j=1:N_t
        found=false;
        for r=1:size(all_teams{j},1)
            row = all_teams{j}(r,:);
            if row(3) > theta; break; end
            if ~any(ismember([row(1),row(2)], used))
                used=[used,row(1),row(2)];
                teams{j}=available_sensors([row(1),row(2)]);
                found=true; break;
            end
        end
        if ~found; ok=false; break; end
    end
    if ok && theta < best_theta
        best_theta=theta; best_assign=teams;
    end
end
Strengths
  • ✓ No toolbox needed
  • ✓ Naturally extends to any N
  • ✓ Efficient in practice
Weaknesses
  • ✗ Greedy feasibility check — not exact
  • ✗ More code than other approaches
  • ✗ Can miss feasible assignments at a given θ
