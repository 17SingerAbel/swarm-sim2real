MIE8888 WSN Multi-Target Tracking · V46

MCMF Assignment Integration and Validation Report

This report summarizes the test design used to validate the new min-cost max-flow interceptor assignment path in V46, while keeping the legacy assignment path available for controlled A/B comparison.

Primary script: example_V46_Yeqi.m Solver: MCMF Legacy retained Full natural run completed

Executive Summary

V46 replaces the interceptor selection step with a global assignment strategy based on min-cost max-flow (MCMF). The validation was intentionally layered: first test the solver, then test the simulation adapter, then test controlled simulation integration, and finally run the clean natural simulation without injection.

Main validation claim: MCMF has been validated as a correct and integrated interceptor assignment module for V46. It computes feasible no-duplicate assignments, handles shortage/conflict cases better than the legacy strategy in controlled tests, runs inside a real simulation loop, and is invoked successfully in the full natural V46 simulation.
Boundary of the claim: the natural Stage 5 run did not produce a simultaneous multi-target assignment event. Therefore, simultaneous-target conflict behavior is validated mainly by adapter tests and injected Stage 3/4 simulation tests, not by a naturally occurring Stage 5 conflict.

What Was Designed

The original legacy strategy selected interceptors from bidding logic inside the simulation. V46 introduces a clearer strategy boundary: 

simulation state
  -> buildAssignmentCostMatrixForCallingTargets(...)
  -> solveInterceptorAssignments(..., use_mcmf)
  -> MCMF or legacy solver
  -> simulation assignment_events and interceptor state updates

MCMF Solver

Each calling target is expanded into interceptor slots. Each candidate sensor has capacity 1, so a sensor cannot be assigned to two targets.

Adapter Layer

The adapter builds the candidate list and cost matrix from simulation-shaped data: active trackers, intercept points, EKF velocity estimates, and sensor positions.

A/B Switch

The wrapper solveInterceptorAssignments(...) keeps the legacy solver available, allowing fair MCMF-vs-legacy comparisons on the same cost matrix.

The MCMF objective is lexicographic: first maximize the number of assigned interceptor slots, then minimize total assignment cost among assignments with the same number of slots.

Stage 1: Module and Adapter Tests

The first layer removes the full simulation from the problem. This makes the test deterministic and lets us directly validate the MCMF assignment behavior.

Five Adapter Test Cases

Test Case Purpose Key Result
testBuildCostMatrixExcludesActiveTrackers Verify active trackers are excluded before candidate bidding. Active trackers [1 2 3 4] are excluded; candidates become [5 6 7 8].
testTwoTargetsPendingSelectionBatchAssignment Verify MCMF can choose the best 4 interceptors from a larger pool. MCMF selects target 1 [6 10] and target 2 [8 9], total cost 0.0582.
testShortageCaseStillProducesPartialAssignment Validate shortage behavior when 4 requested slots compete for only 2 candidates. MCMF distributes sensors across both targets with total cost 0.2125; legacy assigns both to target 1 with cost 0.3669.
testLegacyAndMCMFUseSameAdapterInputs Fair same-input A/B comparison. MCMF total cost 0.8350; legacy total cost 0.9623.
testThreeTargetsWithCandidateShortageUsesAllAvailableSensors Stress test a three-target shortage case. MCMF assigns all 5 available sensors with lower total cost 0.3251; legacy cost is 0.5971.

Why This Validates the Algorithm

  • The tests directly validate the cost-matrix-to-assignment path, so they are not masked by EKF timing, target trajectories, or animation behavior.
  • Shortage and conflict cases demonstrate the main reason MCMF is useful: it can optimize globally across targets rather than filling one target greedily first.
  • The legacy path is kept and tested, so comparisons use the same candidate sensors and cost matrix.

Why This Is Enough to Call MCMF Validated

Validated Claims

  • The MCMF solver produces legal capacity-1 assignments with no duplicate sensors.
  • The adapter correctly excludes active trackers and builds cost matrices from simulation-shaped state.
  • MCMF handles shortage and conflict cases better than legacy in controlled same-input tests.
  • The MCMF assignment path is integrated into V46 and logs assignment_events.
  • MCMF can run inside a real simulation loop and through a full natural run.

Not Claimed Yet

  • We do not claim every full natural run produces simultaneous target conflict.
  • We do not claim MCMF improves every possible handover event.
  • We do not claim natural EKF/loss timing has already produced a multi-target conflict event in Stage 5.
  • We do not claim Stage 4 is no-injection evidence; it is controlled full-run evidence.

The validation is therefore strong but carefully bounded: the module is correct, the adapter is correct, controlled conflict cases show MCMF advantage, full injected simulation is stable, and clean full simulation naturally uses MCMF. The remaining future work is to capture or design a clean natural scenario where simultaneous multi-target handover occurs without injection.
