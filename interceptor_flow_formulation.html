Global Interceptor Allocation via Min-Cost Max-Flow

Graph representation, mathematical formulation, computational complexity, and online feasibility.

1. Graph Representation

The interceptor allocation problem can be represented as a layered flow network. The key idea is to expand each target into m identical interceptor slots. Instead of assigning sensors directly to targets, the algorithm assigns each sensor to one target-slot node.

General k-target, m-slot network

Layer 1 Layer 2 Layer 3 Layer 4 Source s Candidate sensors Target slots Sink t s -----> sensor 1 -----------\ \ sensor 2 ------------\----> (target 1, slot 1) ----\ \ sensor 3 -------------\---> (target 1, slot 2) -----\ \ ... \--> ... ---> t \ sensor n --------------/---> (target 2, slot 1) -----/ \ /---> (target 2, slot 2) ----/ \-----------------------------> ... \--> (target k, slot m) Edge types: 1. s -> sensor i capacity = 1, cost = 0 2. sensor i -> (target j, slot r) capacity = 1, cost = c_ij 3. (target j, slot r) -> t capacity = 1, cost = 0

The source-to-sensor edges enforce that each sensor can be used at most once. The slot-to-sink edges enforce that each target slot can receive at most one sensor. The sensor-to-slot edges encode the actual assignment decisions.

If a sensor-target pair is infeasible, for example because the sensor is already committed, cannot arrive in time, or violates a hard operational constraint, the corresponding edge is simply omitted from the graph.

2. Mathematical Formulation

Let S = {1,2,...,n} be the set of eligible interceptor sensors, and let T = {1,2,...,k} be the set of targets requesting interceptor support. Each target may receive at most m interceptors.

For each feasible sensor-target pair (i,j), let c_ij denote the assignment cost. Define the binary decision variable

x_ij = 1, if sensor i is assigned to target j x_ij = 0, otherwise

The cost of assigning sensor i to target j is derived from the bidding model:

c_ij = w1 * P_home(i) + w2 * P_spatial(i,j) + w3 * P_temporal(i,j) + w4 * P_uncertainty(i,j)

where the individual terms can be defined as:

P_home(i) = ||p_i - p_i^home|| / d_max P_spatial(i,j) = ||p_i - p_j^int|| / d_max P_uncertainty(i,j) = 1 - gamma_ij

Here, p_i is the current position of sensor i, p_i^home is its home position, p_j^int is the intercept point of target j, d_max is a normalization constant such as the maximum network distance, and gamma_ij is the shared confidence value associated with sensor i and target j. The term P_temporal(i,j) is a timing penalty based on the difference between the sensor travel time and the target arrival time at the intercept point.

General constrained assignment model

minimize sum over i in S, j in T c_ij x_ij subject to sum over j in T x_ij <= 1, for all i in S sum over i in S x_ij <= m, for all j in T x_ij in {0,1}

The first constraint ensures that each sensor is assigned at most once. The second constraint ensures that each target receives at most m interceptors.

Coverage-first objective

Since the practical objective is not only to minimize cost but also to maximize target coverage, the optimization should be interpreted in lexicographic form:

  1. maximize the total number of assigned interceptor slots,
  2. among all maximum-coverage assignments, minimize the total assignment cost.

An equivalent shortage-based formulation introduces a shortage variable for each target:

u_j = m - sum over i in S x_ij, u_j >= 0

and solves:

first: minimize sum over j in T u_j then: minimize sum over i in S, j in T c_ij x_ij

This directly captures the design requirement that each target should receive as many interceptors as possible, and should only remain under-served when the number of feasible candidates is insufficient.

Flow-network construction

To convert the problem into min-cost max-flow, each target j is expanded into m slot nodes:

(j,1), (j,2), ..., (j,m)

The flow network is built as follows:

  • Add a source node s and a sink node t.
  • For each sensor i, add edge s -> i with capacity 1 and cost 0.
  • For each feasible pair (i,j) and for each slot r = 1,...,m, add edge i -> (j,r) with capacity 1 and cost c_ij.
  • For each target slot (j,r), add edge (j,r) -> t with capacity 1 and cost 0.

Solving the resulting min-cost max-flow instance yields a globally feasible allocation that satisfies uniqueness, target capacity, and cost optimality under the chosen objective.

3. Computational Complexity

Let n be the number of candidate sensors, k the number of simultaneously calling targets, and m the maximum number of interceptor slots per target. Define q = k m as the total number of target slots.

Step 1: Candidate filtering

Filtering eligible interceptor sensors requires checking each sensor against the active-tracker and feasibility conditions. A conservative complexity bound is:

O(nk)

Step 2: Cost computation

The assignment cost c_ij is computed once per feasible sensor-target pair. Since slots of the same target share the same cost value, cost computation scales as:

O(nk)

Step 3: Graph construction

The flow graph contains:

V = n + km + 2
E = n + nkm + km = O(nkm)

Therefore, graph construction takes:

O(nkm)

Step 4: Min-cost max-flow solution

If the problem is solved using a successive shortest path algorithm with Dijkstra and node potentials, the maximum flow value is:

F = min(n, km)

Each augmentation requires one shortest-path computation of approximately:

O(E log V)

Hence, the overall time complexity is:

O(F E log V) = O(min(n,km) * nkm * log(n+km))

Alternative bipartite matching view

Since the problem is also a weighted bipartite matching between n sensors and q = km target slots, an expanded assignment matrix may be solved by a weighted matching method such as the Hungarian algorithm. If the matrix is padded to square dimension N = max(n, km), then the complexity is:

O(N^3) = O(max(n,km)^3)

This expression is often easier to present in a report, while the min-cost max-flow bound is more general and more flexible for later extensions.

Total online optimization cost

The total runtime per handover event can therefore be summarized as:

O(nk) + O(nk) + O(nkm) + O(min(n,km) * nkm * log(n+km))

The dominant term is the optimization stage itself:

O(min(n,km) * nkm * log(n+km))

4. Online Feasibility Metrics

To claim that the algorithm is suitable for online robotic or WSN deployment, asymptotic complexity alone is not enough. It should also be evaluated with runtime-oriented metrics tied to the handover decision window.

Metric 1: Solve time per reallocation event

Let tau_solve denote the wall-clock time required to complete one interceptor allocation event, including candidate filtering, cost computation, graph construction, optimization, and result decoding.

tau_solve = total optimization latency per handover event

Recommended statistics:

  • mean solve time,
  • median solve time,
  • 95th percentile solve time,
  • worst-case solve time.

Metric 2: Real-time ratio

Let tau_avail be the available decision time between handover trigger and the latest safe dispatch instant. Define the real-time ratio:

R_rt = tau_solve / tau_avail

If R_rt < 1, then the optimization finishes before the decision deadline. If R_rt is significantly below 1, the online feasibility margin is strong.

Metric 3: Deadline satisfaction rate

Define the fraction of handover events solved before their deadlines:

eta_deadline = number of events solved before deadline / total number of events

A value close to 1 indicates that the optimizer is consistently fast enough for online use.

Metric 4: Scaling profile

To support claims of practical deployability, the solve time should be measured while varying:

  • the number of candidate sensors n,
  • the number of simultaneous calling targets k,
  • the slot capacity per target m.

This produces an empirical runtime profile that complements the asymptotic complexity analysis.

Metric 5: Optimality gap versus the current heuristic

To justify replacing the existing heuristic, the improvement in solution quality should be quantified. Let C_heuristic be the total assignment cost produced by the current method, and let C_optimal be the cost produced by min-cost max-flow.

gap = (C_heuristic - C_optimal) / C_optimal

A positive gap shows that the current method is sub-optimal. If the optimality gap is nontrivial while tau_solve remains small, then the proposed algorithm is both more optimal and still online-feasible.

5. Why Online Feasibility is Plausible in This Project

In the current WSN simulation, the problem scale is tightly bounded. There are at most 25 sensors, at most 3 active targets, and at most 2 interceptor slots per target. Therefore:

n <= 25, k <= 3, m = 2, q = km <= 6

The resulting graph is very small:

V = n + km + 2 <= 33 E approx nkm <= 25 * 3 * 2 = 150

This is well within the range of lightweight online optimization. Consequently, online feasibility can be argued from two sides:

  • theoretical boundedness of the optimization problem size,
  • empirical runtime measurements using the metrics above.
A strong evaluation statement would be: the proposed optimizer is considered online-feasible if it solves essentially all handover events before deadline, with a real-time ratio significantly below 1, while also reducing allocation cost relative to the current heuristic.

6. Suggested Positioning in the Report

The current MATLAB implementation may be described as a heuristic bidding-and-conflict-repair strategy that is effective for single-target allocation and partially effective for the two-target case. The proposed min-cost max-flow formulation provides a unified global assignment model, extends naturally to general k-target and m-slot settings, offers exact optimality under the chosen objective, and remains computationally lightweight at the present system scale.
