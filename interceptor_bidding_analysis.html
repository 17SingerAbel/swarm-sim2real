Interceptor Bidding Process Analysis

Prepared for the MEng project on proactive handover in cooperative multi-target tracking.

1. Problem Currently Addressed by the Code

The current interceptor bidding process addresses a prediction-driven interceptor recall and assignment problem. When an active tracker predicts that it will lose a target, the system triggers a handover call and selects new interceptor sensors to move toward a predicted intercept point before the original tracker loses coverage.

  • For each calling target, the code gathers all eligible candidate sensors.
  • Each candidate computes a bid cost, where a lower cost indicates a more suitable interceptor for that target.
  • If only one target is calling, the code selects the two lowest-cost interceptors.
  • If two targets call at the same time and their best two-sensor teams overlap, the code runs an additional conflict-resolution step to produce a non-overlapping 2-plus-2 assignment.

Therefore, the implemented logic is best viewed as a heuristic interceptor selection mechanism for single-target assignment and a partial conflict-resolution mechanism for the two-target case.

A key limitation is that simultaneous conflicts involving three or more targets are not fully handled by the current implementation. The existing conflict-resolution branch is effectively complete only for the two-target case.

2. Target Research Problem

The broader research problem is a global resource-allocation problem with competing targets and limited interceptor resources.

  • There are k targets that may simultaneously request interceptor support.
  • Each target can be assigned at most m interceptors.
  • A pool of idle or reassignable sensors is available as interceptor candidates.
  • Each candidate sensor has a target-dependent assignment cost.
  • The system should maintain unique assignment, so one interceptor cannot be assigned to multiple targets at the same time.
  • The system should assign as many interceptors as possible, ideally up to m per target, and only leave a target under-served when the candidate pool is insufficient.
  • After maximizing feasible coverage, the overall assignment cost should be minimized.

A natural development path is to first optimize the special case k = 2 and m = 2, and then generalize the formulation to arbitrary k and m.

3. Mathematical Form of the Current Method

Let T = {1, ..., k} denote the set of calling targets, and let S = {1, ..., n} denote the set of eligible interceptor candidates. Let c_(i,t) be the bid cost of assigning sensor i to target t.

In the current code, the bid is a weighted sum:

c_(i,t) = w1 P_home(i) + w2 P_spatial(i,t) + w3 P_temporal(i,t) + w4 P_uncertainty(i,t)
  • P_home penalizes the displacement of a sensor from its home location.
  • P_spatial penalizes the distance from the sensor to the target intercept point.
  • P_temporal penalizes poor arrival timing relative to the target motion.
  • P_uncertainty penalizes low shared confidence in the target estimate.

For a single target t, the current logic is equivalent to the following binary optimization problem:

min sum over i in S of c_(i,t) x_(i,t) subject to sum over i in S of x_(i,t) = 2 x_(i,t) in {0,1}

Because the team cost is additive, the implementation simply selects the two lowest-cost sensors for the calling target.

For two simultaneous targets, the code applies a repair-based strategy:

  1. First, it independently computes the best two-sensor team for each target.
  2. Second, it checks whether the selected teams overlap.
  3. If overlap exists, it performs a minimax-style enumeration over a reduced candidate subset and selects the non-overlapping assignment that minimizes the worst team cost.

This means the current approach does not solve one unified global optimization problem. Instead, it first obtains local optima and then repairs conflicts when necessary.

4. Why the Current Method is Sub-optimal

  • It is not a single globally optimized formulation.
  • It may miss better global assignments because it starts from per-target local minima.
  • Its objective changes across cases: single-target selection minimizes additive cost, while conflict repair for two targets uses a minimax criterion.
  • The method is only fully implemented for the two-target simultaneous-conflict case.
  • It does not rigorously encode the priority of maximizing assignment coverage before minimizing cost.
  • When the candidate pool is insufficient, it does not provide a clean and systematic partial-allocation rule.

Its main strengths are simplicity, low computational burden, and easy integration into the current monolithic MATLAB simulation. Therefore, it is best described as a practical conflict-aware heuristic rather than a globally optimal multi-target allocation algorithm.

5. More Efficient and More Optimal Alternatives

A more systematic solution is to formulate the interceptor assignment as a global constrained optimization problem.

Let x_(i,t) = 1 if sensor i is assigned to target t, and 0 otherwise.

sum over t in T of x_(i,t) <= 1 for all sensors i sum over i in S of x_(i,t) <= m for all targets t x_(i,t) in {0,1}

A suitable lexicographic objective is:

  1. First, maximize the total number of assigned interceptor slots.
  2. Second, among all maximum-coverage assignments, minimize the total assignment cost.

Equivalently, one may introduce shortage variables u_t = m - sum over i in S of x_(i,t) and minimize shortage before minimizing cost. This directly captures the requirement that each target should receive as many interceptors as possible, and only be under-served when the candidate pool is insufficient.

Two strong algorithmic options follow from this formulation.

  • Min-cost max-flow: Duplicate each target into m target slots, connect each sensor to eligible slots with edge cost c_(i,t), and solve a global min-cost max-flow problem. This gives an exact and computationally efficient solution for the small and medium-size instances relevant to this project.
  • MILP: Use binary decision variables and solve the allocation as a mixed-integer linear program. This is clean to present mathematically and also yields a global optimum at the current problem scale.

For the current simulation scale, such as up to 25 sensors, 3 targets, and 2 interceptor slots per target, both approaches are computationally practical and are far more systematic than pairwise conflict repair.

6. Recommended Research Positioning

A clear research narrative is the following. The current code uses a heuristic bidding and conflict-resolution scheme that works reasonably for single-target assignment and partially for the two-target case. However, it is not a unified global optimizer and does not naturally scale to general multi-target competition. A stronger formulation is to model interceptor selection as a capacity-constrained global assignment problem and solve it using min-cost max-flow or MILP. This provides guaranteed uniqueness, graceful degradation when resources are insufficient, and globally optimal assignments under the stated objective.
