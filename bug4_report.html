1. Problem Statement

The simulation tracks up to 3 targets simultaneously. Each target maintains exactly 2 active trackers (PRIMARY + SECONDARY). When a tracker predicts it will lose its target, it broadcasts an interceptor call. Available idle sensors bid, and the system assigns 2-sensor teams to intercept the target before it is lost.

When two or more targets call simultaneously, teams may compete for the same sensors. The conflict resolver must find a globally optimal disjoint assignment — no sensor can serve two teams at once. The existing code handles the N = 2 case with a minimax search, but when N = 3 targets call at the same time the block is silently skipped and the system falls back to a greedy independent assignment that ignores cross-target conflicts.

3. Mathematical Model

3.1 Definitions

S = { s1, s2, …, sk } // pool of available (non-tracker) sensors, k ≤ ~22 T = { t1, t2, …, tN } // conflicting targets (N ∈ {2, 3}) B ∈ ℝk×N // bid matrix: B[i,j] = bid cost of si for target tj Pj ⊆ S, |Pj| = 2 // team assigned to target j (exactly 2 sensors) Cj = Σs∈Pj B[s, j] // team cost for target j

3.2 Constraints

|Pj| = 2 ∀j ∈ {1,…,N} // each target gets exactly 2 sensors Pi ∩ Pj = ∅ ∀i ≠ j // disjointness — no sensor shared Pj ⊆ S // sensors drawn from available pool

3.3 Objective — Minimax

min P1,…,PN max j=1…N Cj ≡ min P1,…,PN max j Σs∈Pj B[s, j] subject to the constraints above
Interpretation: Minimise the cost of the worst-served target. This is the bottleneck team assignment problem — a variant of quadratic assignment where the bottleneck (max) objective replaces the usual sum. It is NP-hard in general, but with N ≤ 3 and k ≤ 22 it is tractable by exhaustive enumeration or ILP.

3.4 ILP Formulation (compact form)

Variables: xij ∈ {0, 1} 1 if sensor si is assigned to target tj θ ∈ ℝ+ auxiliary variable = max team cost (the bottleneck) Objective: min θ Constraints: Σi xij = 2 ∀j (2 sensors per target) Σj xij ≤ 1 ∀i (each sensor assigned at most once) Σi B[i,j]·xij ≤ θ ∀j (team cost ≤ bottleneck) xij ∈ {0, 1}

4. Five Candidate Algorithms

1
Extended Exhaustive Enumeration (6-loop) Optimal within top-k

Direct extension of the existing 4-loop N=2 code to 6 loops for N=3. Iterate over all C(k,2) candidate pairs for each of the 3 targets from a shared top-k pool, keep only disjoint triples, record max(cost1,cost2,cost3), return the minimum.

Complexity: O(k2N) = O(k6) raw. With top-8 filter: union ≤ 16 sensors → C(16,2)³ ≈ 27,000 iterations. Runs in <1 ms. 
% Extend existing block (lines 987-1039)
elseif length(all_calling_targets) == 3
    n_top = min(8, length(available_sensors));
    [~, si1] = sort(all_target_bids(:,1));
    [~, si2] = sort(all_target_bids(:,2));
    [~, si3] = sort(all_target_bids(:,3));
    top = unique([available_sensors(si1(1:n_top));
                  available_sensors(si2(1:n_top));
                  available_sensors(si3(1:n_top))]);
    K = length(top);
    best_cost = inf;  best_assign = [];
    for i1 = 1:K-1
     for i2 = i1+1:K
      r1 = [top(i1),top(i2)];
      for i3 = 1:K-1
       for i4 = i3+1:K
        if isempty(intersect(r1,[top(i3),top(i4)]))
         r2 = [top(i3),top(i4)];
         for i5 = 1:K-1
          for i6 = i5+1:K
           r3 = [top(i5),top(i6)];
           if isempty(intersect(r2,r3)) && isempty(intersect(r1,r3))
            c1 = sum(all_target_bids(ismember(available_sensors,r1),1));
            c2 = sum(all_target_bids(ismember(available_sensors,r2),2));
            c3 = sum(all_target_bids(ismember(available_sensors,r3),3));
            mc = max([c1,c2,c3]);
            if mc < best_cost
             best_cost = mc;  best_assign = {r1,r2,r3};
            end
           end
          end
         end
        end
       end
      end
     end
    end
end

  • Minimal code change to existing structure
  • No toolbox required
  • 6 nested loops is hard to read
  • Top-k filter may miss global optimum
  • O(k⁶) grows if top-k filter widened
2
ILP via MATLAB intlinprog Globally Optimal

Encode the problem as an Integer Linear Program using the compact formulation in §3.4. MATLAB's intlinprog solves it exactly, over all k sensors and N targets, with no top-k pruning required. No enumeration loops needed.

Complexity: ILP is NP-hard in general, but branch-and-bound on k×N=66 binary variables with N=3 constraints solves in <1 ms (benchmark confirmed in CLAUDE.md analysis). No top-k filter needed. 
% Decision vars: x = vec(X) where X ∈ {0,1}^(k×N), plus θ
N_t = length(all_calling_targets);  k = length(available_sensors);
% x = [x_11,x_21,...,x_k1, x_12,...,x_kN, theta]  length = k*N_t + 1
n_vars = k * N_t + 1;

% Objective: min theta (last variable)
f = [zeros(1, k*N_t), 1];

% Equality: sum_i x_ij = 2  for each j
Aeq = zeros(N_t, n_vars);
for j = 1:N_t
    Aeq(j, (j-1)*k+1 : j*k) = 1;
end
beq = 2 * ones(N_t, 1);

% Inequality: sum_j x_ij <= 1  (each sensor at most once)
A_sense = zeros(k, n_vars);
for i = 1:k
    for j = 1:N_t
        A_sense(i, (j-1)*k + i) = 1;
    end
end

% Inequality: sum_i B[i,j]*x_ij <= theta  for each j
A_theta = zeros(N_t, n_vars);
for j = 1:N_t
    A_theta(j, (j-1)*k+1:j*k) = all_target_bids(:,j)';
    A_theta(j, end) = -1;
end

A   = [A_sense; A_theta];
b   = [ones(k,1); zeros(N_t,1)];
lb  = zeros(n_vars, 1);
ub  = [ones(k*N_t,1); inf];
int = 1:k*N_t;  % integer variables (x only; theta is continuous)

opts = optimoptions('intlinprog', 'Display', 'off');
[sol, ~, flag] = intlinprog(f, int, A, b, Aeq, beq, lb, ub, opts);

if flag > 0
    X = reshape(sol(1:k*N_t), k, N_t);
    for j = 1:N_t
        assigned = available_sensors(X(:,j) > 0.5);
        % assign team 'assigned' to target all_calling_targets(j)
    end
end

  • Handles arbitrary N automatically
  • Clean, compact code
  • Requires Optimization Toolbox

  • Toolbox license dependency
3
Permutation Greedy (all N! orderings) Near-Optimal

For each of the N! permutations of target ordering, greedily assign the cheapest available 2-sensor team to each target in that order. Return the permutation that minimises the maximum team cost. With N=3 this is only 6 orderings — O(N!·k²) total.

Complexity: N! × O(k²) = 6 × k² ≈ 6 × 484 ≈ 2,900 ops. Negligible cost. Sub-optimal in theory but finds the true minimax solution in most practical cases because the bid landscape is smooth. 
% N! = 6 permutations for N=3
perms_T = perms(1:N_t);
best_cost = inf;  best_assign = cell(1,N_t);

for p = 1:size(perms_T, 1)
    order = perms_T(p,:);
    used = [];
    team = cell(1,N_t);
    max_c = 0;
    valid = true;

    for jj = 1:N_t
        j = order(jj);
        free = setdiff(1:k, used);
        if length(free) < 2; valid = false; break; end

        best_pair_cost = inf;  best_pair = [];
        for a = 1:length(free)-1
         for b = a+1:length(free)
          c = all_target_bids(free(a),j) + all_target_bids(free(b),j);
          if c < best_pair_cost
           best_pair_cost = c;
           best_pair = [free(a), free(b)];
          end
         end
        end
        used = [used, best_pair];
        team{j} = available_sensors(best_pair);
        max_c = max(max_c, best_pair_cost);
    end

    if valid && max_c < best_cost
        best_cost = max_c;
        best_assign = team;
    end
end
  • No toolbox required
  • Generalises to any N trivially
  • Very readable code
  • Not guaranteed optimal (greedy-within-permutation)
  • Can miss cases where splitting top-bidders optimally requires non-greedy choice
4
Branch & Bound with Pruning Optimal

Build a recursive search tree over targets. At each node, choose the cheapest remaining team for the current target. Prune branches as soon as the partial max cost exceeds the current best known solution. The bound is tight for minimax because the actual max can only increase as more teams are assigned.

Complexity: O(k2N) worst case (same as exhaustive), but in practice pruning eliminates >95% of branches when bid distributions are spread out. Average case much closer to O(k²·N). 
% Recursive B&B — call as: [c,a] = bb(targets, available, 0, inf, {})
function [best_c, best_a] = bb(targets, avail, cur_max, ub, assign)
  if isempty(targets)
    best_c = cur_max;  best_a = assign;  return;
  end
  j = targets(1);  rest = targets(2:end);
  best_c = ub;  best_a = [];
  k = length(avail);
  for a = 1:k-1
   for b = a+1:k
    c_team = B(avail(a),j) + B(avail(b),j);
    new_max = max(cur_max, c_team);
    if new_max >= best_c; continue; end  % prune
    new_avail = avail(setdiff(1:k,[a,b]));
    [c2, a2] = bb(rest, new_avail, new_max, best_c, [assign, {[avail(a),avail(b)]}]);
    if ~isempty(a2) && c2 < best_c
     best_c = c2;  best_a = a2;
    end
   end
  end
end
  • Provably optimal
  • Usually very fast in practice
  • No toolbox needed
  • Recursive MATLAB is slow (function call overhead)
  • Harder to debug than flat loops
  • Worst case same as exhaustive

Binary Cost Relaxation + Sorted Scan Efficient Sub-optimal

Sort all possible 2-sensor teams per target by cost (ascending). Then do a two-pointer scan across the N sorted lists: maintain a threshold θ and check if N disjoint teams all with cost ≤ θ exist. Binary search over θ using team-cost thresholds as candidates. Feasibility at each θ reduces to a bipartite matching (can be checked greedily in O(k·N)).

Complexity: O(k²·N·log(k²)) for sorting + O(k²·N) for threshold scan = O(k²·N·log k). For k=22, N=3: ≈4,300 ops. Sub-optimal because feasibility check uses greedy matching, but minimax gap is typically <5%. 
% Pre-sort all teams per target
all_teams = cell(N_t, 1);
for j = 1:N_t
    pairs = [];
    for a = 1:k-1
     for b = a+1:k
      pairs(end+1,:) = [a, b, all_target_bids(a,j)+all_target_bids(b,j)];
     end
    end
    [~,si] = sort(pairs(:,3));
    all_teams{j} = pairs(si,:);   % sorted by cost
end

% Collect all distinct threshold candidates (team costs)
thresholds = unique(vertcat(all_teams{:})(:,3));

% Binary search / linear scan for minimum feasible theta
best_theta = inf;  best_assign = [];
for theta = thresholds'
    % Greedy check: for each target, pick cheapest team with cost <= theta
    %               that doesn't reuse sensors already claimed
    used = [];  feasible = true;  assign = {};
    for j = 1:N_t
        found = false;
        for row = 1:size(all_teams{j},1)
            t = all_teams{j}(row,:);
            if t(3) > theta; break; end
            if ~any(ismember([t(1),t(2)], used))
                used = [used, t(1), t(2)];
                assign{j} = available_sensors([t(1),t(2)]);
                found = true;  break;
            end
        end
        if ~found; feasible = false; break; end
    end
    if feasible && theta < best_theta
        best_theta = theta;  best_assign = assign;
    end
end
  • No toolbox needed
  • Efficiently finds near-minimax solution
  • Naturally extends to N > 3
  • Greedy feasibility check is not optimal (can miss valid assignments)
  • More code than other approaches

6. Recommendation

Short term — lowest effort

Algorithm 1 (6-loop exhaustive) is the direct extension of what already exists for N=2. You add one more pair of nested loops, change the if N==2 to if N==2 ... elseif N==3 ..., and the rest of the assignment code (winner → INTERCEPTING) is shared. This is a <40 line change with no new abstractions.

Long term — cleanest generalisation

Algorithm 3 (permutation greedy) handles any N in the same loop, requires no toolbox, and produces near-optimal results in practice because the minimax gap for smooth bid distributions is typically <2%. It also removes the fragile if N==2 / elseif N==3 branching entirely.
