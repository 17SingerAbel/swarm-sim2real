Revision Memo for YS1 Final Report

YS1 Report Title Revision Highlight

这份 memo 不改原 PDF 或 DOCX，只把你这篇 report 的标题层级重新讲清楚。重点不是一般性的 “wording cleanup”，而是把你的方法贡献准确地顶到标题里：一是 assignment objective 从 minmax 的 worst-case protection 转向 MCMF 的 global cost-optimal assignment；二是当后来的 target 选中一个已经在执行 interception 的 sensor 时，系统会把受影响 target 一起纳入 joint reselection，而不是让后来的 target 直接覆盖之前的 assignment。

Current Report: MCMF-Based Interceptor Assignment for Cooperative Multi-Target Tracking in a Mobile WSN Scope: Title + Headings Only Key Shift: From MinMax to MCMF Mechanism: Conflict-Aware Joint Reselection

1. What Is Being Highlighted

这次 revision 的核心不是把标题改得更长，而是把叙事逻辑改对。你现在真正想强调的贡献，应该从 “MCMF is used” 升级成 “why MCMF replaces the old logic, and what new conflict handling behavior V46 adds compared with the earlier implementation”。

From MinMax to MCMF Conflict-Aware Joint Reselection
Before

原来的标题重心

更像是在说 “我用了一个 MCMF-based assignment method”，但没有把你相对原始 minmax 逻辑到底改了什么讲出来。

  • 没有明确交代 objective 从 fairness-oriented / worst-case protection 转成 total-cost-oriented global assignment。
  • 没有明确交代 V46 新增的 joint reselection 机制。
  • 读者容易把它理解成 “只换了一个 solver”，而不是 “method + conflict logic 都变了”。
After

改完之后的标题重心

新的标题体系会直接告诉读者：你做的是从 legacy minmax 到 MCMF 的方法转变，并且加入了 conflict-aware joint reselection 来避免 later target sequentially overwriting an ongoing interception assignment。

  • 把 “why MCMF” 讲清楚，而不是只说 “use MCMF”。
  • 把 “protect continuity of ongoing interception” 讲清楚，但不误写成 unconditional protection of the earlier target。
  • 让 Section 4 和 Section 5 的逻辑与真实贡献完全对齐。
一句话总结： 你要强调的不是 “旧 target 永远优先”，而是 “后来的 target 不能靠顺序优势直接抢走正在执行 interception 的 sensor；一旦冲突出现，受影响 targets 会被一起拉进来重新优化。”

2. Recommended Main Title

下面三种都可以用，但推荐第一种，因为它最完整地覆盖了你的两个核心贡献，而且不会把 “protect previous target” 说得过头。

Recommended

Main Title Option 1

From MinMax to MCMF: Conflict-Aware Joint Interceptor Reselection for Cooperative Multi-Target Tracking in Mobile WSNs

这个版本最适合你现在的 narrative。

  • From MinMax to MCMF 直接点明你相对之前方法的核心变化。
  • Conflict-Aware Joint Interceptor Reselection 直接对应 “later target 选到正在 interception 的 sensor 时，要把受影响 target 一起纳入 reselection”。
  • 语义稳，不会暗示 earlier target 一定被无条件保留。
Alternative

Main Title Option 2

MCMF-Based Interceptor Assignment with Conflict-Aware Joint Reselection in Mobile Wireless Sensor Networks

这个版本更直接、更偏 method naming。

  • 优点是简洁，适合你想让标题更像 algorithm paper。
  • 缺点是没有像 Option 1 那样清楚地写出 “from minmax to MCMF” 的比较关系。
Alternative

Main Title Option 3

From Worst-Case-Protective MinMax to MCMF: Joint Interceptor Reassignment Under Inter-Target Conflict in Mobile WSNs

这个版本更强调 objective shift。

  • 适合你想明显突出 old objective 是 worst-case-protective。
  • 缺点是语气更“理论化”，没有 Option 1 那么自然。
不建议直接写： protect previous target 或 compared with Naeimeh's code 进总标题。前者太绝对，后者太像内部开发对比，不像正式 report title。

5. Narrative Alignment Notes

最后一部分是为了防止标题改完了，但正文还是在讲旧逻辑。下面这些 note 可以帮助你保证标题、Section 4、以及结果讨论三者说的是同一件事。

  • 标题里如果写了 From MinMax to MCMF，那么 Section 4 的 opening paragraph 就必须明确说明：旧方法的 objective 是 minimize the worst team cost，而新方法是先 maximize filled slots、再 minimize total cost。
  • 标题里如果写了 Conflict-Aware Joint Reselection，那么 Section 5 的 conflict case 就必须明确说明：later target 不能靠触发顺序直接拿走一个已经在执行 interception 的 sensor；一旦发生 reuse conflict，受影响 targets 会被一起重选。
  • “保护之前的 target” 可以作为直觉解释，但正式写法最好不要把它说成 rule。更准确的表述是：系统防止 sequential overwrite，并通过 joint reselection 保持 ongoing interception continuity。
  • 你的结果讨论不需要把 V46 写成 “永远保老 target”；它真正做的是在冲突发生时，把 old target 也带回 optimization scope，而不是让 later target 单边决定结果。
Optional English framing sentence for the Introduction or Section 4:
Compared with the original minmax-based implementation, V46 replaces worst-case-oriented assignment with an MCMF formulation and introduces conflict-aware joint reselection when a later target selects a sensor already committed to another ongoing interception task.

这句话不是必须直接贴进 report，但它很好地压缩了你的两项核心贡献，也能帮助你检查标题和正文有没有对齐。
